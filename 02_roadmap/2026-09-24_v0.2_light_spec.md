# modelwatch v0.2 light

## 0. Why this replaces the v0.1 run path

v0.1 worked as engineering and failed as a habit: the 2026-09-23 full run got 857 usable scores of
1,500 because of API credits, 429s and an interrupt, and it needed ten API keys and a Docker
sandbox to say anything. Wilco's rule (2026-09-24): standard questions, run weekly in the
harnesses he already uses, answers kept, one judge scores, one curve grows. Nothing else.

Kept from v0.1: the 30 calibrated items (as the question source), `results\` as append-only
store, `report.py` and the vendored Chart.js, `flatten.py`'s row idea. Parked, not deleted:
Inspect tasks, roster of API models, Docker sandbox, spend guard, cross-vendor judge, external
importers (`import --all` stays available for a monthly public-picture refresh, optional).

## 1. Shape

```
questions\v1\Q01.md .. Q20.md     one file per question: frontmatter (id, area, version,
                                   fixture, rubric 0..5, expected notes), then the prompt text
fixtures\<name>\                   small folders a question works in (from v0.1 tasks\fixtures)
answers\<ISO week>\<harness>\<model>\Qxx.md, Qxx.meta.json, Qxx.diff (edit tasks only)
answers\<ISO week>\cowork\<model>\Qxx.md    pasted by hand when Wilco wants a Cowork column
judgements\<ISO week>\<harness>\<model>\Qxx.json   {score, reason, judge_model, judged_at}
results\weekly.ndjson              append-only, one row per judged answer
reports\weekly.html                the curve: per area, per harness+model, one point per week
scripts\run_week.ps1               runs every question in every harness, saves answers
scripts\judge_week.ps1             one judge scores every unjudged answer, appends rows
scripts\report_week.ps1            calls uv run modelwatch report --weekly
```

Row in `results\weekly.ndjson`: `week, run_date, harness, harness_version, model (as the harness
reports it), question_id, question_version, area, score (0..5), reason, judge_model,
duration_s, tokens_hint, notes`.

## 2. Questions

Twenty, derived from the 30 v0.1 anchors by the build session, no new authoring: 5 hub edits,
3 injection, 4 voice (2 NL, 2 EN), 3 Dutch, 2 coding (fix the failing test in fixture repo X,
the harness runs pytest itself), 3 skill following. Each question is self-contained prose the
harness can act on inside its fixture folder. Question text stays private, as before. A rubric
is five one-line criteria; the judge returns 0 to 5 as the count met, plus one sentence.

## 3. Weekly run (Monday, one script, about 30 minutes wall)

`run_week.ps1 -Week 2026-W40` (default: current ISO week). For each harness in `config\harnesses.json`
(v0.2: `claude`, `codex`) and each model listed for it:
- copy the question's fixture folder to a temp dir, `cd` there;
- `claude -p "<prompt>" --model <model> --output-format json` or `codex exec --model <model> --json "<prompt>"`
  (exact flags VERIFY against `claude --help` and `codex exec --help` on the day; record
  `claude --version` and `codex --version` in `meta.json`);
- save stdout as `Qxx.md`, the JSON envelope fields (model reported, duration, tokens when present)
  as `Qxx.meta.json`, and for edit and coding questions `git diff --no-index` of the fixture as `Qxx.diff`
  plus pytest output when the question has tests;
- one attempt per question per week; a failure is saved as `Qxx.md` with `notes=harness_error`,
  never retried silently. The week is the repeat: variance shows as week-to-week jitter.
Models per harness: the default model of that harness plus one named alternative, both as the
harness reports them, recorded per week. No API keys, no OpenRouter, plan usage only.

## 4. Judge (one model, disclosed)

`judge_week.ps1`: for every answer without a judgement, one `claude -p` call with the question,
rubric, answer, diff and pytest output, asking for JSON `{score, reason}`; judge model is
`config\judge.json` (Claude Opus, exact model string recorded from the response). Deterministic
pre-checks from v0.1 (`no_em_dash`, `full_paths`, `frontmatter_intact`) run first and are
passed to the judge as facts. Every report carries one line: "Judge: <model>. Claude answers
are judged by a Claude model; expect self-preference bias, not corrected." Calibration:
once a quarter Wilco scores the same 10 answers by hand, agreement is logged in
`03_logs\calibration.ndjson` as in v0.1.

## 5. Report

`report --weekly` renders `reports\weekly.html`: six small charts (one per area), x = ISO week,
one line per harness+model; a table "this week vs last week" per harness+model with the delta
and the two questions that moved most; the judge line; a coverage line (answers judged / planned).
No SE bands in v0.2 (one sample per week); after eight weeks the report adds a four-week rolling
mean per line.

## 6. Steps, one session each

1. Week 39/40: questions v1 (20 files), fixtures moved, `run_week.ps1` for `claude` only, first
   answers folder. Done when 20 answers exist for two Claude models. Tag `v0.2.0-alpha.1`.
2. `codex exec` column, `judge_week.ps1`, `weekly.ndjson`, `report --weekly`. Done when one
   full week (2 harnesses x 2 models x 20 questions = 80 rows) is judged and charted.
   Tag `v0.2.0-alpha.2`.
3. Windows Task Scheduler entry (Monday 06:00, run then judge then report), Cowork paste
   column recognised, README rewritten for the light path, v0.1 run path marked legacy in
   `AGENTS.md`. Done when a scheduled run completes unattended. Tag `v0.2.0`.

## 7. Out of scope

Ten-model API rosters. Docker sandboxes (the harness is the sandbox). Cross-vendor judging.
Repeats within a week. Public benchmark re-runs. Publishing question text.
